# Absence rebate credits

Proposed single-mess schema extension for #189. Maintainer review of the schema and secretary approval/settlement permissions is required before migration/deployment. No second tenant, payment gateway, snacks enum or invented wing dimension is added: the existing schema has breakfast/lunch/dinner and no wing field.

The secretary configures integer paise rates, minimum days and notice hours. Initial rates are zero, so applications remain closed until configured. Each application snapshots the policy version; edits do not change existing estimates. Dates are inclusive IST calendar days (maximum 31). Notice is measured before midnight IST on the first day. The student sees an estimate, not confirmed funds. New bookings during pending/approved/settled absences are blocked under the same student transaction lock; existing bookings must be cancelled using the normal flow.

Settlement is allowed only after the last absent day ends. Each included meal/date receives at most one policy-rate credit. Any BOOKED/SERVED/NO_SHOW included booking, or a cancellation at/after cutoff, excludes that meal. Timely cancellations permit credit. Multiple dishes/counts never multiply credit. Extras earn none. Approval/rejection is PENDING-only. A unique ledger row makes settlement retries idempotent. Per-student advisory locks fence overlapping applications and settlement; per-request row locks fence review transitions. Audit, ledger and status changes share one transaction. Ledger/audit updates and deletions are rejected by database triggers; request transitions include a sequenced hash chain. Hashes are integrity aids, not proof against a database administrator.

Students read only their own applications/credit queries. Actions re-read database roles. Bulk operations are bounded to 50 and report partial failures. Monthly CSV and printable statements use IST settlement-posting month, include zero-credit outcomes and sum committed ledger entries. CSV quotes cells and neutralizes spreadsheet formulas. No invoice/debit ledger exists: displayed credit is cumulative posted credit, not a spendable balance or bank transfer. More than 10,000 statement rows fails explicitly instead of silently truncating.

Run `npm run test:rebates`, the integration suite against a newly provisioned disposable database, lint, typecheck and build. `npm run rebates:reconcile` takes an existing secretary ID and handles at most 1,000 approved requests per invocation; run again for the remainder. It is available for a maintainer's scheduler; no schedule/service is installed. Existing destructive seed reruns may be blocked by immutable financial history: use a fresh disposable database for seed testing.

For a fully isolated integration run, install PostgreSQL client/server binaries and run `npm run test:rebates:private`. It initializes a new loopback-only cluster, deploys migrations, creates a one-use isolation marker, runs the suite, and stops that cluster in `finally`. Set `PGBIN` to your PostgreSQL bin directory (Windows defaults to PostgreSQL 18). It never uses your configured `DATABASE_URL`; diagnostic cluster files remain in the OS temporary directory. Node, Prisma and tsx are the existing project tools.
